# Prompt 07 — Update docs and traceability after an approved decision

Update documentation only for a decision the owner has approved or a verified implementation fact. Do not invent or silently promote assumptions into confirmed decisions.

## Required steps
1. Read the decision register and all affected canonical docs.
2. Identify every document, prompt, test ID, migration note, and phase plan affected.
3. Update the decision register with status, rationale, date, approving actor, alternatives where material, and impacts.
4. Update canonical requirements; avoid duplicating rules where a cross-reference is better.
5. Update acceptance/traceability and tests.
6. Search for contradictions and stale references.
7. Report files changed and remaining unresolved issues.

Never edit a confirmed product decision merely because implementation would be easier otherwise. If technical evidence indicates it is unsafe or impossible, prepare a proposal and wait for owner approval.
